# 🌙 Sleep-time Compute 完整使用指南

## 📖 什么是 Sleep-time Compute？

Sleep-time Compute 是六花的"睡眠记忆整合"系统，灵感来自人类睡眠时的记忆巩固过程。

### 工作原理

```
白天（实时）                    夜晚（凌晨3点）
─────────────                  ──────────────
快速记录碎片                    深度反思整合
  ↓                              ↓
[碎片1] 要去北京出差            识别重复记忆
[碎片2] 提醒准备行李     →      提取行为模式
[碎片3] 北京天气                生成连贯叙事
[碎片4] 喜欢希尔顿              
                                ↓
                            契约者本周计划去北京出差，
                            关心天气，偏好希尔顿酒店
```

---

## 🎯 核心功能

### 1. 识别并合并重复记忆

**问题**：
```
记忆1: 契约者喜欢喝咖啡
记忆2: 契约者喜欢咖啡
记忆3: 用户说他喜欢喝咖啡
```

**Sleep-time Compute 处理后**：
```
✅ 保留: 记忆1（最早的）
❌ 删除: 记忆2、记忆3（标记为 tombstone）
📊 结果: 数据库体积减少，检索精度提升
```

### 2. 提取长期行为模式

**输入碎片**：
```
[周二] 契约者开会了
[周二] 今天又要开会
[周二] 周会开始
```

**提取模式**：
```
🧬 行为模式: "契约者每周二开会"
📈 置信度: 0.7 → 0.8 → 0.9（每次验证后提升）
```

### 3. 生成连贯叙事

**输入碎片**：
```
[08-19] 要去北京出差
[08-19] 订了机票
[08-20] 查北京天气
[08-20] 预订希尔顿
```

**生成叙事**：
```
📖 Episode: "本周北京出差计划"
契约者本周计划去北京出差，已订机票，关心当地天气，
预订了希尔顿酒店。显示出对商务出行的周密准备。
```

## ⚙️ 配置说明

### 默认配置

```json
{
  "enabled": true,           // 是否启用
  "execution_time": "03:00", // 每天凌晨3点
  "lookback_days": 7,        // 回溯7天
  "model": "deepseek-chat"   // 使用 DeepSeek v3
}
```

### 可调参数

#### 1. **执行时间** (execution_time)

推荐时间段：
- **凌晨 2:00-4:00**: 最佳，用户通常休息
- **凌晨 1:00-2:00**: 可选，更早整合
- **凌晨 4:00-6:00**: 可选，接近起床时间

⚠️ 避免白天执行：会消耗 API 调用额度

#### 2. **回溯天数** (lookback_days)

| 天数 | 适用场景 | 碎片数量 | 执行时间 |
|------|---------|---------|---------|
| 3天 | 轻度使用 | <50条 | ~10秒 |
| 7天 | 日常使用 ✅ | 50-200条 | ~20秒 |
| 14天 | 重度使用 | 200-500条 | ~40秒 |
| 30天 | 深度整理 | 500+条 | ~60秒 |

#### 3. **模型选择** (model)

| 模型 | 成本/次 | 速度 | 效果 | 推荐度 |
|------|---------|-----|------|--------|
| **DeepSeek v3** | ¥0.004 | 快 | 优秀 | ⭐⭐⭐⭐⭐ |
| Claude Sonnet 3.5 | ¥0.03 | 中 | 优秀 | ⭐⭐⭐⭐ |
| Claude Opus 4 | ¥0.15 | 慢 | 最强 | ⭐⭐⭐ |
| Qwen Max | ¥0.02 | 快 | 良好 | ⭐⭐⭐⭐ |
| 自定义 | 取决于模型 | - | - | - |

**推荐**: DeepSeek v3（性价比最高）

## 🔧 高级配置

### 使用自定义模型

支持任意 OpenAI 兼容模型：
```json
{
  "model": "gpt-4-turbo"
}
```

常见模型名称：
- OpenAI: `gpt-4-turbo`, `gpt-4o`
- Claude: `claude-opus-4-20250514`, `claude-3-5-sonnet-20241022`
- 通义千问: `qwen-max-latest`, `qwen-plus`
- DeepSeek: `deepseek-chat`, `deepseek-reasoner`

### 定时任务调度

当前实现：**后台线程 + 时间检查**

工作原理：
1. 应用启动时创建后台线程
2. 每 30 分钟检查一次当前时间
3. 如果在执行窗口（凌晨 2-4 点），执行整合
4. 执行后休眠 2 小时，避免重复

### 与 Archivist 的关系

| 功能 | Archivist | Sleep-time Compute |
|------|-----------|-------------------|
| 执行频率 | 实时（每 50 条碎片） | 定时（每天 1 次） |
| 执行速度 | 快（无 LLM） | 慢（调用 LLM） |
| 整合深度 | 浅（规则拼接） | 深（语义理解） |
| Token 消耗 | 0 | ~2000 tokens |

**互补关系**：
- Archivist 负责快速轻量整合
- Sleep-time Compute 负责深度语义整合

## ⚠️ 注意事项

### 1. API 调用限制

- 每次执行消耗 ~2000 tokens
- 确保 API 额度充足
- DeepSeek 基本无限制

### 2. 执行时间选择

- ❌ 不要选择白天：影响正常使用
- ✅ 推荐深夜：用户休息时间
- ✅ 避开高峰：凌晨 API 响应更快

### 3. 数据备份

- Sleep-time Compute 会删除重复记忆
- 建议定期备份 `rikkai.db`
- 删除的记忆标记为 `tombstone`，可恢复

## 🐛 故障排查

### 问题 1: 执行失败

**现象**: 控制台显示 "❌ LLM 调用失败"

**原因**:
- API 密钥无效
- 网络连接问题
- 模型名称错误

**解决**:
1. 检查 API 配置
2. 测试网络连接
3. 尝试更换模型

### 问题 2: 没有自动执行

**现象**: 凌晨 3 点没有执行

**原因**:
- 六花未启动
- `schedule_sleep_time_compute()` 未调用
- 设置中已禁用

**解决**:
1. 确保六花持续运行
2. 检查 main.py 是否调用了启动函数
3. 检查设置中的启用开关

### 问题 3: 碎片数量不足

**现象**: "碎片数量不足（5 < 10），跳过整合"

**原因**: 回溯期内碎片少于 10 条

**解决**: 正常现象，无需处理
